### 1.4 Windows 代理配置标准 (WinINET vs WinHTTP)
- **文档主题**：Differences Between WinINET and WinHTTP
- **官方链接**：https://learn.microsoft.com/zh-cn/windows/win32/winhttp/wininet-vs-winhttp
- **核心要点**：
  - WinINET 代理配置存储于用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`，影响浏览器及通用应用。

### 1.5 NCSI (网络连接状态指示器) 与 NLA (网络位置感知) 架构与判定机制
- **文档主题**：Network Connectivity Status Indicator (NCSI) Architecture and Troubleshooting
- **官方链接**：https://learn.microsoft.com/zh-cn/windows-server/networking/ncsi/ncsi-frequently-asked-questions
- **核心要点**：
  - Windows 任务栏右下角的网络状态图标（“已连接 Internet” vs “无 Internet 访问 / 地球图标”）完全由 NCSI 判定，其判定逻辑独立于应用程序的实际 TCP 流量。
  - **主动探测机制**：
    1. **DNS 探针**：向 `dns.msftncsi.com` 发起解析请求，期望返回标准响应 `131.107.255.255`。
    2. **HTTP 探针**：向 `http://www.msftconnecttest.com/connecttest.txt` 发起纯文本 HTTP GET，期望返回内容为 `Microsoft Connect Test`。
  - **为什么图标“无网络”但实际能上网？**
    - 若本地运行了透明代理、Clash 等网络工具，或局域网网关劫持了 HTTP/DNS 请求，导致 NCSI 探针未能获得完全一致的内容匹配，Windows 会判定为“未连接到 Internet”。此时实际上普通 TCP/HTTPS 流量完全畅通。
    - 若 `NlaSvc`（网络位置感知服务）处于停止状态，系统将无法正确将网络接口与网络配置文件（Profile）绑定，同样会导致图标显示异常。
  - **安全准则**：严禁通过脚本随意修改注册表 `EnableActiveProbing` 或篡改探针服务器，只读采集探针状态足以辅助准确定位问题。

### 1.6 Windows 6 大核心网络系统服务的职责与故障影响
- **文档主题**：Windows Core Networking Services
- **官方链接**：https://learn.microsoft.com/zh-cn/windows/client-management/system-services-reference
- **服务职责清单**：
  1. **Dhcp (DHCP Client)**：
     - **职责**：负责向路由器/局域网 DHCP 服务器发起 DHCPREQUEST，动态获取、续租和维护本机 IPv4/IPv6 地址、默认网关及 DNS 服务器列表。
     - **影响**：若停止，无法动态获取 IP，网络断开后无法重新协商分配地址。
  2. **Dnscache (DNS Client)**：
     - **职责**：负责解析、集中缓存全系统的域名解析结果，优化应用程序的 DNS 解析延迟。
     - **影响**：若停止，DNS 查询性能严重劣化，部分依赖系统统一解析库的 WinRT/UWP 应用可能无法联网。
  3. **nsi (Network Store Interface Service)**：
     - **职责**：负责收集底层路由、接口连接与状态消息，并统一广播分发给用户模式应用程序和系统网络栈。
     - **影响**：网络底层核心。若停止，应用程序将无法感知网络连接的变化。
  4. **Wlansvc (WLAN AutoConfig)**：
     - **职责**：负责配置、探测、连接和断开 IEEE 802.11 无线适配器，管理 Wi-Fi 扫描、802.1X / WPA 认证及配置文件。
     - **影响**：若停止，Windows 无法扫描无线热点，无法自动连接 Wi-Fi，任务栏 Wi-Fi 列表彻底变空。
  5. **NlaSvc (Network Location Awareness)**：
     - **职责**：负责采集和存储网络的配置信息，判断当前网络属于“公用网络”还是“专用网络”，并驱动 NCSI 判定。
     - **影响**：若停止，系统将网络识别为“无法识别的网络”，Windows 防火墙可能会施加最严格的安全隔离规则阻断局域网通信。
  6. **WinHttpAutoProxySvc (Windows HTTP Web Proxy Auto-Discovery Service)**：
     - **职责**：负责执行 Web 代理自动发现 (WPAD) 协议并下载、执行 PAC（Proxy Auto-Configuration）脚本。
     - **影响**：在运行代理客户端或受控企业网络中，若此服务异常，依赖 WinHTTP 的系统更新、后台传输及某些桌面软件将无法正确绕行直连或走代理。

### 1.7 网卡电源管理节能机制与偶发断流掉线 (微软官方排障)
- **文档主题**：Power management settings on a network adapter

### 1.8 DHCP 租约生命周期与 RFC 2131 标准续租行为
- **文档主题**：Dynamic Host Configuration Protocol (RFC 2131)
- **权威标准**：IETF RFC 2131 (March 1997)
- **核心机制**：
  - **T1 计时器 (50% 租期)**：客户端必须在租约过去一半时，主动向租约授予服务器（DHCPServer）发送单播 DHCPREQUEST 报文请求续租。
  - **T2 计时器 (87.5% 租期)**：如果 T1 续租未收到 ACK，在租约达到 87.5% 时，客户端将进入 REBINDING 状态，向全网发送广播 DHCPREQUEST 报文寻找任意可用 DHCP 服务器。
  - **租约过期 (100%)**：若租约到期仍未获得确认，客户端必须立即释放现有 IP 地址并回退到 APIPA（169.254.x.x）或重新发送 DHCPDISCOVER。
  - **只读准则**：本工具计算并展示租约剩余时间与状态，但绝不执行 `ipconfig /renew`，避免破坏现有的 IP 会话状态。

### 1.9 IPv6 双栈机制与 IPv6 黑洞超时 (RFC 6555 Happy Eyeballs)
- **文档主题**：Happy Eyeballs: Success with Dual-Stack Hosts (RFC 6555 / RFC 8305)
- **核心机制**：
  - 现代操作系统普遍支持 IPv4/IPv6 双栈。当域名解析同时返回 A 记录与 AAAA 记录时，系统会优先发起 IPv6 连接。
  - **IPv6 黑洞风险**：若本地网络接口分配了全局 IPv6 地址或默认路由（::/0），但上级网关或运营商光猫并没有真正的 IPv6 公网转发能力，客户端发起的 IPv6 SYN 报文将陷入黑洞（无 RST 也无 ACK）。客户端必须等待 TCP 连接超时（数秒至十数秒）后才会回退到 IPv4。这常被用户直观感知为“刚连接网络时网页打不开，要等很久才突然能上网”。
  - **诊断依据**：本工具明确区分“纯 IPv4 正常”、“完整双栈正常”、“IPv6 默认路由缺失”与“IPv6 存在默认路由但无外网连通（潜在黑洞）”，精准帮助用户排查延迟根因。

## 2. 硬件原厂与 Wi-Fi 协会技术规范 (Intel / MediaTek / Wi-Fi Alliance)

### 2.1 802.11 状态机与驱动主动断开 (Reason 8003 / 8002)
- **标准依据**：IEEE Std 802.11™-2020 (Wireless LAN MAC and PHY Specifications)
- **权威解释**：
  - **Event 8003 (网络被驱动程序断开连接)**：通常由 Wi-Fi 芯片的固件管理单元（MAC Layer Firmware）触发。当信噪比（SNR）瞬时劣化至解调阈值以下、或连续数个 Beacon 帧丢失（Beacon Loss Timeout）时，驱动会向 OS NDIS 报告主动断开连接。
  - **RSSI 255**：在 Windows NDIS 体系中，RSSI（接收信号强度指示）以负 dBm 或百分比表示。值 `255`（0xFF）在 NDIS 驱动规范中代表 `NdisMediaRadioOff` 或 `NDIS_RADIO_STATUS_UNSPECIFIED`（即射频通道当前无测量值或不可用）。

### 2.2 WPA3 / 802.11i 密钥握手超时 (Event 11006)
- **技术要点**：
  - 动态密钥交换（4-Way Handshake）必须在 AP 设定的微秒级时间窗口内完成。
  - 若在此期间系统发生高负载 CPU 调度抢占、或由于天线阻挡发生数据帧碰撞丢包，握手计时器超时即会引发 Event 11006 报错。
  - 随后网卡通常需要等待退避时间（Backoff Timer）重新发起 Association 请求。
