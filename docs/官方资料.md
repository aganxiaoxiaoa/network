## 1. 微软官方技术文档 (Microsoft Learn)

### 1.1 Windows 网络体系结构与 NDIS (Network Driver Interface Specification)
- **文档主题**：NDIS 6.x 核心网络架构与适配器状态机
- **官方链接**：https://learn.microsoft.com/zh-cn/windows-hardware/drivers/network/overview-of-ndis-6-0
- **核心要点**：
  - Windows 网络适配器的启用/禁用（`Disable-NetAdapter` / `Enable-NetAdapter`）涉及底层的 Miniport 驱动卸载、IRP 撤销及 PCI 电源状态切换（D0 -> D3hot -> D0）。
  - 对正在处理高吞吐量数据包的无线网卡强行执行状态重置，极易导致底层固件（Firmware）挂起或驱动死锁。
  - **技术结论**：在未取得完全物理控制或非严重宕机情况下，严禁在常规脚本中自动化调用物理适配器重置。

### 1.2 PnPUtil 官方命令行规范 (驱动导出最佳实践)
- **文档主题**：PnPUtil Command Syntax (受控只读导出)
- **官方链接**：https://learn.microsoft.com/zh-cn/windows-hardware/drivers/devtest/pnputil-command-syntax
- **核心要点**：
  - `pnputil.exe /export-driver * <TargetDirectory>` 是微软官方唯一推荐的无损、纯只读驱动程序导出机制。
  - 该指令仅执行文件复制与驱动包完整性解包，不触碰正在运行的驱动服务，不引发硬件重启或重协商。
  - **合规依据**：本工具箱选用 `pnputil /export-driver` 作为驱动备份模块的唯一底层实现，杜绝了直接操作 DriverStore 注册表带来的系统损坏风险。

### 1.3 Windows PowerShell 5.1 兼容性与 StrictMode
- **文档主题**：`Set-StrictMode` 与类型系统演进
- **官方链接**：https://learn.microsoft.com/zh-cn/powershell/module/microsoft.powershell.core/set-strictmode
- **核心要点**：
  - 在 PowerShell 5.1 下，启用 `Set-StrictMode -Version 2.0` 时，若访问单项标量对象的 `.Count` 属性，或访问不存在的 PSCustomObject / Registry 动态属性，将直接触发致命异常并中断脚本。
  - **规范落地**：本工具箱对所有集合访问均强制实施 `@($result).Count` 包装，对注册表键值采用 `.PSObject.Properties[...]` 预检，确保在 Windows 10/11 的 PowerShell 5.1 环境下 100% 稳定运行。

### 1.4 Windows 代理配置标准 (WinINET vs WinHTTP)
- **文档主题**：Differences Between WinINET and WinHTTP
- **官方链接**：https://learn.microsoft.com/zh-cn/windows/win32/winhttp/wininet-vs-winhttp
- **核心要点**：
  - WinINET 代理配置存储于用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`，影响浏览器及通用应用。
  - WinHTTP 代理配置属于系统服务与系统更新（Windows Update / BITS），由底层注册表存储并通过 `netsh winhttp` 管理。
  - **只读原则**：排查代理问题时，只能读取上述两处配置进行交叉比对，绝对不能使用 `netsh winhttp reset proxy` 盲目重置。

## 2. 硬件原厂与 Wi-Fi 协会技术规范 (Intel / MediaTek / Wi-Fi Alliance)

### 2.1 802.11 状态机与驱动主动断开 (Reason 8003 / 8002)
- **标准依据**：IEEE Std 802.11™-2020 (Wireless LAN MAC and PHY Specifications)
- **权威解释**：
  - **Event 8003 (网络被驱动程序断开连接)**：通常由 Wi-Fi 芯片的固件管理单元（MAC Layer Firmware）触发。当信噪比（SNR）瞬时劣化至解调阈值以下、或连续数个 Beacon 帧丢失（Beacon Loss Timeout）时，驱动会向 OS NDIS 报告主动断开连接。
  - **RSSI 255**：在 Windows NDIS 体系中，RSSI（接收信号强度指示）以负 dBm 或百分比表示。值 `255`（0xFF）在 NDIS 驱动规范中代表 `NdisMediaRadioOff` 或 `NDIS_RADIO_STATUS_UNSPECIFIED`（即射频通道当前无测量值或不可用）。

### 2.2 WPA3 / 802.11i 密钥握手超时 (Event 11006)
- **技术要点**：
  - 动态密钥交换（4-Way Handshake）必须在 AP 设定的微秒级时间窗口内完成。
  - 若在此期间系统发生高负载 CPU 调度抢占、或由于天线阻挡发生数据帧碰撞丢包，握手计时器超时即会引发 Event 11006 报错。
  - 随后网卡通常需要等待退避时间（Backoff Timer）重新发起 Association 请求。
