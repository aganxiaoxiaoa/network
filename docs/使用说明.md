## 1. 工具定位与设计理念

本工具箱是专为 Windows 宿主机在网络异常、离线或排查故障时设计的**即插即用、纯只读网络诊断与硬件驱动受控备份工具**。

### 核心设计原则
1. **纯只读绝不修改**：严禁调用任何网卡启停、IP 重置、DNS 刷新或代理修改命令，杜绝二次断网。
2. **即插即走零残留**：拔除 U 盘后，宿主机上不残留任何计划任务、服务、注册表自启项或进程。
3. **环境隔离与互斥**：自动探测并避让宿主机本地已运行的网络看门狗，提供单实例互斥锁。
4. **数据安全脱敏**：收集日志时对 Wi-Fi SSID、MAC、公网 IP 等敏感信息进行掩码处理，绝不抓取明文密钥。

## 3. 快速上手

### 方式一：双击启动 (交互式菜单)
1. 插入 U 盘，在资源管理器中打开 `E:\Network-Recovery-USB\`。
2. 双击运行 `START-DIAGNOSIS.cmd`。
3. 弹出控制台窗口，自动加载配置并呈现如下菜单：
   ```text
    =======================================================================
            Windows 10/11 便携网络诊断工具箱 (USB 纯只读安全版)            
    =======================================================================
       [1] Execute Read-Only Network Diagnostics (执行纯只读网络健康与配置诊断)
       [2] Generate Diagnostic Log Bundle (ZIP) (生成诊断报告与脱敏压缩包)
       [3] Export Third-Party Network Driver Catalog (导出第三方网络驱动清单与包)
       [4] Analyze Disconnection Timeline (断网时间线关联分析)
       [5] Save Health Baseline (保存当前健康基线)
       [6] Compare With Baseline (与基线比对差异)
       [0] Exit (退出工具箱)
    =======================================================================
    ```
4. 输入序号并回车即可执行。

### 方式二：命令行非交互模式 (适合脚本或自动化调用)
打开 PowerShell 或 CMD，进入 `E:\Network-Recovery-USB\` 目录：

```powershell
# 1. 打印全量只读健康诊断
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action FullHealth

# 2. 执行断网时间线关联分析 (默认回溯 24 小时)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action Timeline

# 3. 指定时间线回溯窗口 (如最近 1 小时)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action Timeline -HoursBack 1

# 4. 生成脱敏诊断压缩包
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action Bundle

# 5. 导出网络驱动备份 (需管理员权限)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action BackupDrivers

# 6. 保存当前健康基线 (退出码: 0成功, 1错误)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action SaveBaseline

# 7. 与基线比对差异 (退出码: 0无差异, 2有差异, 1错误)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action CompareBaseline

# 8. 指定特定基线文件比对
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action CompareBaseline -BaselineFile .\output\baseline\baseline-20260910-050720.json

# 9. 查看帮助
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\NetworkDiagnostics.ps1 -Action Help
```

## 4. 核心功能详解

### 4.1 完整只读网络健康诊断 (Action: FullHealth)
分层排查网络故障，不发任何写操作，全面覆盖 12 大维度：
- **[1/12] 本地网络看门狗安全互斥检测**：检测本地 D 盘是否存在运行中的 `NetworkRecoveryWatchdog` 计划任务或后台进程，统计活跃的代理栈（Clash/ProxyStack）进程数量，自动锁定只读模式。
- **[2/12] IPv4 默认路由与网关探测**：核查 `0.0.0.0/0` 路由是否存在、下一跳网关 IP、接口索引与有效跃点（Route Metric + Interface Metric）。
- **[3/12] IPv6 默认路由与双栈状态检测 (新增)**：查询 `::/0` 默认路由是否存在及分配的全球单播 IPv6 地址（GUA），明确区分“纯 IPv4 正常单栈”、“完整双栈”与“IPv6 默认路由存在但外部不通（黑洞超时风险）”。
- **[4/12] 活动物理适配器核验与电源管理配置 (新增)**：读取网卡硬件类型、介质状态、协商速率及 MAC 地址；只读读取网卡电源管理配置（`AllowComputerToTurnOffDevice`），若开启省电选项则提示其断网风险并指导用户在设备管理器手动修改。
- **[5/12] 无线链路质量指标 (新增)**：解析无线接口状态，提取工作频段（2.4GHz/5GHz/6GHz）、信道、协商速率（Tx/Rx Rate）、信号百分比与估算 RSSI（dBm），说明弱信号（<50%）或信道拥塞与 802.11 4-Way 密钥协商超时导致断流的直接关联。对 SSID 和 BSSID 自动脱敏。
- **[6/12] IP 配置与 DHCP 租约详细信息 (新增)**：读取 IPv4 地址（重点预警 APIPA `169.254.x.x`）及 DNS 服务器；通过 WMI/CIM 采集 DHCP 租约获取时间、到期时间并计算剩余有效期，结合 RFC 2131 阐述 50% (T1) 和 87.5% (T2) 续租行为，明确声明本工具绝不发起续租。
- **[7/12] NCSI 系统网络连通性判定与探针状态 (新增)**：读取 `Get-NetConnectionProfile` 与系统注册表 NCSI 探针参数（`EnableActiveProbing`、`ActiveWebProbeHost` 等），阐述任务栏图标与真实网络访问的判定差异。
- **[8/12] 动态网关连通性 (参考信号)**：发起单次轻量 ICMP Ping 测试默认网关，评估本地局域网物理链路连通性。
- **[9/12] 公网直连 TCP 握手探测**：绕过系统代理，直接建立原生 TCP 握手测试（覆盖阿里 DNS `223.5.5.5:53`、腾讯 DNS `119.29.29.29:53`、百度 `www.baidu.com:443` 等），精确测量毫秒级公网直连延迟。
- **[10/12] 域名系统 (DNS) 解析测试**：针对测试域名（如 `www.microsoft.com`）执行 `Resolve-DnsName`，检验本地 DNS 递归解析能力。
- **[11/12] 系统代理配置只读核对**：同时读取当前用户的 WinINET 代理（开关、ProxyServer、PAC 脚本、绕行规则）及系统级 WinHTTP 代理，排查代理配置偏差。
- **[12/12] Windows 核心网络服务状态 (新增)**：全面监控 6 大关键网络服务（`Dhcp`、`Dnscache`、`nsi`、`Wlansvc`、`NlaSvc`、`WinHttpAutoProxySvc`）的运行状态与启动类型，并输出每个服务在系统网络协议栈中的具体职责说明。

### 4.2 诊断报告与脱敏归档包 (Action: Bundle)
在 `output\` 目录下自动生成以时间戳命名的诊断 ZIP 包（例如 `DiagnosticBundle_20260910_014500.zip`），内部包含：
- `Report.json`：全量诊断数据的结构化 JSON，便于机器分析；
- `Report.txt`：格式化的文本版诊断摘要，便于直接查阅；
- `SystemInfo.txt`：系统版本、网络适配器配置、路由表快照；
- `Diagnostics.log`：本次运行的完整日志。
> **脱敏安全特性**：所有导出文件均对 Wi-Fi SSID、BSSID、物理 MAC 地址后段及公网 IPv4 地址自动执行掩码脱敏（例如 `Wi***`、`XX:XX:XX:XX:5E:2B`、`123.***.***.12`）。

### 4.3 导出第三方网络驱动 (Action: BackupDrivers)
在网络彻底瘫痪或怀疑网卡驱动损坏时，可使用本功能将当前系统内已安装的第三方网卡驱动提取备份至 U 盘 `backups\Drivers\`：
- 底层仅调用 Windows 官方命令 `pnputil.exe /export-driver`；
- 执行前严格检测 U 盘剩余空间（必须大于 500MB，不足则拒绝执行）；
- 纯只读导出，绝不执行 `/add-driver`、`/delete-driver` 或 `/restart-device`。

### 4.4 断网时间线关联分析 (Action: Timeline)
针对历史上曾发生过的物理 Wi-Fi 偶发断网事故，提供一键式多源事件时序关联能力：
- **四路只读数据来源**：
  1. **WLAN Operational 日志**：精准捕获无线网络断开（ID 8003/11004）、重连失败（ID 8002）、动态密钥交换超时（ID 11006）及关联握手全过程；
  2. **System 网络 Provider 日志**：枚举并监控真实无线驱动（`mtkwlex`）、系统 WLAN 服务、DNS 客户端超时（ID 1014）、TCP/IP 协议栈（ID 4207）及服务控制管理器状态流转（ID 7036/7040/7045）；
  3. **本机看门狗日志 (可选)**：通过 `Select-String` 只读过滤提取看门狗在时间窗内的状态诊断（DIAG）、告警（WARN）与执行动作（ACTION），无此文件时优雅跳过；
  4. **现代待机会话与电源事件 (新增)**：全面纳管系统内核电源事件（`Microsoft-Windows-Kernel-Power`），捕获进入低功耗状态（ID 109）、退出低功耗唤醒恢复（ID 41/577）、现代待机网络连通性状态变更（ID 172: Disconnected/Connected）及硬件状态更新（ID 125/521）。
- **现代待机时序关联分析**：
  - 自动重构低功耗睡眠会话时间区间（`[SessionStart, SessionEnd]`）；
  - 针对所有 WLAN 断开事件（ID 8003/11004）与电源转换时序执行精细时间差比对，自动划分 4 种分布：
    * **会话期内断开**：断网发生在系统低功耗睡眠维持期间；
    * **唤醒后即时断开**：断网发生在退出低功耗唤醒后的 30 秒容限窗口内（判定与睡眠唤醒直接关联）；
    * **进入睡眠前夕断开**：断网发生在进入低功耗状态前的 60 秒临近窗口内；
    * **完全清醒期断开**：断网发生在系统正常活跃使用期，与电源状态转换无关。
- **只读电源诊断 HTML 报告生成**：
  - 工具自动探测当前会话权限：若在**管理员权限**下运行，会自动调用官方只读命令 `powercfg /sleepstudy` 与 `powercfg /systempowerreport`，将完整的交互式可视化 HTML 报告直接生成至 U 盘 `logs\sleepstudy_*.html` 与 `logs\powerreport_*.html`；
  - 若在**非管理员权限**下运行，工具自动触发安全优雅跳过，仅输出文本提示，绝不报错中断。
  - **安全红线**：本工具绝不调用任何 `powercfg` 写操作命令（如 `/setactive`、`/change`、`/hibernate` 等）。
- **自动化统计与指标**：汇总统计断开次数、失败重连、密钥超时、异常 RSSI 数值（如 255）及看门狗触发动作清单，不丢弃任何未知事件 ID。
- **隐私脱敏机制**：SSID、BSSID/MAC、代理节点名（节点名称脱敏为 `[ProxyNode]`）全自动掩码处理，杜绝敏感凭据泄露。
- **完整时序落盘**：完整时序明细自动写入 `logs\timeline_*.log`，控制台呈现汇总统计面板与最近 20 条事件流。
- **免责声明**：输出包含官方定性声明——“以上仅为时间相关性，不构成因果结论。”

### 4.5 健康基线保存与差异比对 (Action: SaveBaseline / CompareBaseline)
用于在网络正常或已知健康状态下采集并持久化静态基准，便于在发生故障时快速定位被篡改或漂移的核心网络参数：
- **纯只读原则声明**：本功能**绝不提供任何“从基线恢复/重置”能力**，严防改写代理配置或重置协议栈导致二次断网。
- **基线快照保存 (`SaveBaseline`)**：
  采集当前网络配置与健康状态结构化快照，写入 `output\baseline\baseline-yyyyMMdd-HHmmss.json`，并更新指针文件 `output\baseline\latest.txt`（严格只记录纯相对文件名，绝无盘符，确保换电脑即插即用）。
- **字段严格分层**：
  1. **核心稳定字段 (13 项，参与异常判定)**：`InterfaceGuid`, `MacAddress`, `InterfaceDescription`, `HardwareInterface`, `DhcpEnabled`, `DnsServers`, `DefaultGateway`, `ProxyEnable`, `ProxyServer`, `ProxyOverride`, `AutoConfigURL`, `ServiceStartTypes`, `IPv6HasDefaultRoute`。
  2. **易变参考指标 (10 项，不视为异常)**：`IPv4Address`, `DhcpRemainingMinutes`, `LinkSpeed`, `ReceiveRate`, `TransmitRate`, `SignalPercent`, `RssiEstimated`, `RouteMetric`, `EffectiveMetric`, `ServiceStatuses`。
- **比对结果输出与日志落盘 (`CompareBaseline`)**：
  比对明细完整记录至 `logs\baseline_compare_*.log`，并在控制台高亮输出稳定字段差异与易变字段变化。
- **退出码标准定义**：
  - `0`：稳定字段无差异（或基线保存成功）；
  - `2`：发现核心稳定字段差异（潜在网络配置异常）；
  - `1`：工具执行错误（基线目录不存在、指定文件缺失、JSON 损坏等）。

### 4.6 Windows 11 位置隐私权限与无线链路指标说明
在运行 `[5/12] 无线链路质量指标` 诊断时，部分环境可能会显示限制提示：
- **现象描述**：控制台输出提示“Windows 11 隐私与位置限制：查询无线链路质量详情需要开启系统‘位置’权限或以管理员身份运行。底层 WlanQueryInterface 返回拒绝访问 (Error 5)”，导致无法读取当前 Wi-Fi 的 RSSI、信道、频段及信号百分比。
- **底层原因**：Windows 11 安全机制强化了位置隐私管控，由于 Wi-Fi 接入点 BSSID 和信号特征可用于精准推断地理位置，系统将无线扫描信息纳为位置敏感数据。未显式授权位置访问权限的标准命令行进程调用 `netsh wlan show interfaces` 或原生 API 时会被系统安全子系统直接拒绝（Access Denied / Error 5）。
- **用户手动开启路径**：
  若需获取完整无线指标，用户可自行在 Windows 系统中开启：
  `Windows 设置 → 隐私和安全性 → 位置`，将“位置服务”及相关桌面应用访问开关置为“开”。
- **只读保证与优雅降级**：
  **本工具严格恪守纯只读边界，绝不自动调用任何 API 或注册表去开启、修改系统的隐私或位置设置**。若用户未开启位置权限，工具会自动触发安全降级逻辑，跳过敏感 Wi-Fi 硬件扫描，其余 11 层网络诊断及时间线分析完全不受任何影响。
- **RSSI 指标排障重要性**：
  在本机 2026-09-10 物理断网事故日志中，曾记录到 `RSSI: 255` 异常值。在 802.11 规范中，RSSI 为 255 通常是硬件驱动返回的特殊枚举值，代表“网络探测不可用 / 完全丢失 AP 信号”。能够读取真实的 RSSI 信号强度，是判断网络异常究竟是源于“物理距离与射频盲区导致搜不到信号”，还是源于“协议栈握手认证超时”的关键核心线索。

### 4.7 现代待机架构 (Modern Standby) 与网卡高级属性语义分类排查说明
在运行 `[4/12] 活动网络适配器核验与硬件电源管理` 时，工具会分别检测系统的电源待机架构以及网卡高级属性中的省电与稳定性选项：
- **现代待机 (Modern Standby / S0) 与传统电源管理的关系**：
  在支持 S0 低电量待机的现代轻薄本上，Windows 取消了网卡设备属性页中的“电源管理”选项卡（即取消了传统的“允许计算机关闭此设备以节约电源”复选框）。因此通过传统 API `Get-NetAdapterPowerManagement` 查询时会返回 `Unsupported`。这属于现代待机平台的正常设计表现，并不代表网卡没有节能机制。
- **网卡高级属性的三维语义分类体系 (彻底杜绝误报)**：
  为了避免将多值枚举选项（如“1. 无首选项”、“1. 最高”）误报为“省电项已启用”，工具建立了由配置文件驱动的语义化三维分类体系，并在控制台及日志中清晰输出三个独立指标：
  1. **需关注激进省电类**（布尔开关，开启可能引发微睡眠断流/掉线）：
     - 涵盖：`LowPowerEnable (省电)`、`U-APSD Support`、`MIMO Power Save`、`Selective Suspend` 等。
     - 若处于开启状态，标记为 `[需关注-已开启]` 并作为核心排查重点；若为关闭状态，标记为 `[需关注-已关闭]`。
  2. **正常网络卸载与睡眠唤醒类**（布尔开关，现代待机机型预期开启）：
     - 涵盖：`ARP Offload for WOWLAN`、`NS Offload`、`GTK Rekey for WOWLAN`、`唤醒幻数据包`、`唤醒模式匹配`、`Packet Coalescing` 等。
     - 此类属于 S0 待机下维持网络代理响应的预期机制，处于开启状态时标记为 `[正常类-已开启]`。
  3. **多值枚举选择型配置**（非布尔开关，多值参数选择）：
     - 涵盖：`Preferred Band (首选频带)`、`Roaming Aggressiveness (漫游主动性)`、`Transmit Power Level (传输功率)`、`Throughput Booster` 等。
     - 仅作为驱动工作策略记录，标记为 `[枚举项]`，不作启用/禁用布尔判定，彻底消除此前因匹配 `^1.` 导致的伪阳性误报。
- **用户手动调整排查路径**：
  若遇到笔记本睡眠唤醒断网、微睡眠掉线或 Wi-Fi 搜不到信号，用户可按需手动调整：
  `此电脑 (右键) → 管理 → 设备管理器 → 网络适配器 → 目标 Wi-Fi 网卡 (右键属性) → 高级`，在属性列表中找到上述省电项（例如将 `U-APSD Support` 改为 `已禁用`）。
- **工具纯只读承诺**：
  **本工具恪守绝对只读原则，绝不自动调用任何指令或驱动 API 去修改网卡的高级属性或省电模式**。全量 17 项属性均被安全记录至 `logs\adapter_advanced_properties_*.log`，以便用户在不改变系统状态的前提下查阅完整的驱动配置基线。

### 4.8 WLAN 逐次故障与断开取证分析说明 (Timeline 子小节)
在运行 `-Action Timeline` 时，工具会自动触发 WLAN 逐次故障取证子小节，帮助排查历史 Wi-Fi 断网与重连失败的具体特征：
- **故障事件与正常流程的严格区分**：
  - **故障类事件**：
    - `Event 8003`：无线网络被断开 (Disconnected)。**仅本事件计入断开次数**。
    - `Event 8002`：无线连接/重连失败 (Failed to connect)。记录其信号强度 RSSI 及失败原因。
    - `Event 11006`：无线安全握手失败/动态密钥交换超时 (Security failed)。记录其对端路由器 AP 的 BSSID MAC。
  - **正常流程类事件**：
    - `Event 11004`：无线安全停止 (Security stopped)。**特别标注：属于正常安全会话拆除流程，非故障事件**，绝不与断开事件混算。
    - `Event 8000 / 8001 / 11000 / 11001 / 11005 / 11010`：无线关联与安全握手正常步骤。
- **逐次取证字段含义**：
  - `TimeCreated`：事件发生的精确时间戳。
  - `EventId`：WLAN-AutoConfig 事件 ID (8003, 8002, 11006)。
  - `ReasonCodeRaw` / `ReasonCodeHex`：底层结构化原因码（十进制与十六进制），非手工推测。
  - `ReasonTextFromApi`：通过微软官方 API `WlanReasonCodeToString` 动态翻译的标准含义（严禁静态硬编码）。
  - `ReasonTextFromEvent`：事件日志中附带的系统本地化描述文本。
  - `PrecedingEventId`：该次故障发生前 60 秒内最近一条 WLAN 事件 ID，用于排查前置时序诱因。
  - `PeerBssid`：发生安全失败时的对端 AP MAC 地址（仅 11006 包含，自动遵循 3 段前缀脱敏规则）。
  - `Rssi`：连接失败时的接收信号强度指示（仅 8002 包含，255 代表射频无有效测量）。
  - `Ssid`：关联的 Wi-Fi 名称（自动遵循首尾字符保留脱敏规则）。
- **活动网卡驱动基线记录**：
  - 自动只读提取当前活动无线网卡的 `DriverVersion`、`DriverDate`、`DriverProviderName`、`InfName`，并记录 `netsh wlan show drivers` 原始信息至 `logs\` 目录。
  - **只记录不评价**：不联网查询，不给出任何更新与改动建议。
- **免责声明**：
  `以上仅为时间相关性与统计分布，不构成因果结论。`

## 5. 常见问题排查 (FAQ)

**Q1: 为什么工具启动时提示“本地网络看门狗正在运行”？**
> 答：这是安全保护特性。工具检测到宿主机 D 盘正在运行 `NetworkRecoveryWatchdog` 监控脚本。为防止两个工具同时运行引发状态冲突，本工具自动锁定为纯只读观察模式，绝不触碰或修改网络。

**Q2: 运行工具需要管理员权限吗？**
> 答：执行只读健康诊断（`FullHealth`）和生成脱敏报告包（`Bundle`）**完全不需要管理员权限**，普通用户权限即可正常运行。仅有“导出驱动（`BackupDrivers`）”功能因调用系统底层的 `pnputil.exe` 导出接口，需要以管理员身份运行控制台。

**Q3: 为什么 `quarantine` 文件夹里的文件无法双击运行？**
> 答：该目录是历史事故版本的物理隔离区。为防止用户或运维误触造成网络再次中断，所有脚本入口均被强制更名为 `.disabled` 后缀，严禁恢复和运行。
