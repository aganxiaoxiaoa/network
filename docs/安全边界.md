================================================================================
【核心原则】避免再次断网 (Zero Network Impact) | 证据优先 (Evidence First)

## 1. 核心安全红线 (Forbidden Operations)

本工具箱在代码架构、指令调用与业务逻辑层面，**绝对禁止**包含以下任何一项具有网络状态变更副作用的操作：

| 类别 | 严禁调用的命令 / API | 风险说明 | 本工具合规实现 |
| :--- | :--- | :--- | :--- |
| **网卡状态修改** | `Disable-NetAdapter`<br>`Enable-NetAdapter`<br>`Restart-NetAdapter` | 重启物理网卡会导致 Wi-Fi 芯片瞬时掉电或驱动重置，极易诱发固件崩溃断网 | 仅调用 `Get-NetAdapter`、`Get-NetAdapterStatistics` 进行只读查询 |
| **IP / 租约变更** | `ipconfig /release`<br>`ipconfig /renew`<br>`arp -d` | 释放 IP 会立即中断已有 TCP 连接；DHCP 续租失败会导致接口掉线 | 仅调用 `Get-NetIPAddress`、`Get-NetIPConfiguration` 进行只读信息读取 |
| **协议栈与重置** | `netsh winsock reset`<br>`netsh int ip reset`<br>`netcfg -d` | 重置底层 Winsock 目录和 TCP/IP 栈会破坏 LSP、VPN 虚拟网卡驱动并强制要求重启 | 严禁包含此类指令；相关旧版代码已全量物理隔离封存 |
| **DNS 缓存修改** | `ipconfig /flushdns`<br>`Clear-DnsClientCache` | 刷新本地 DNS 解析缓存可能导致瞬时解析延迟增加或冲突 | 仅使用 `Resolve-DnsName` 测试单次域名解析能力 |
| **代理注册表篡改** | `Set-ItemProperty ... Internet Settings`<br>`netsh winhttp reset proxy` | 强行重置代理可能破坏企业内网、合规网关或特定网络分流环境 | 仅通过注册表只读读取 `ProxyEnable`、`ProxyServer` 及 `netsh winhttp show proxy` |
| **网络凭据泄露** | `netsh wlan show profile key=clear` | 明文导出 Wi-Fi 密码违背企业与个人数据安全准则 | 绝不抓取明文密钥；所有 Wi-Fi SSID 均进行字符串掩码脱敏 |
| **系统持久化污染** | `schtasks /create`<br>`sc.exe create`<br>`New-Service`<br>写入注册表 Run 键 | 留在宿主机上的后台脚本会破坏宿主机独立性，随时间推移失控 | 拔出即走，不创建任何驻留进程、计划任务或服务 |

## 2. 本地看门狗避让与互斥机制

宿主机本地 D 盘已常驻运行着由系统计划任务托管的看门狗脚本：
- **计划任务名称**：`NetworkRecoveryWatchdog`
- **监控脚本路径**：`D:\agentNeural Network Knowledge Base\network\auto_network_recovery.ps1`
- **托管管理脚本**：`D:\agentNeural Network Knowledge Base\network\manage_watchdog.ps1`

### 互斥防御策略
1. **进程与任务静态侦测**：
   工具启动初始化时，`Test-LocalWatchdogRunning` 会主动扫描：
   - 计划任务 `NetworkRecoveryWatchdog` 是否存在且处于 `Running` 状态；
   - 运行中进程是否包含 `auto_network_recovery.ps1`。
2. **强制降级只读模式**：
   一旦发现看门狗处于活动状态，控制台立即高亮输出提示：
   `[WARN] 检测到系统本地网络看门狗正在运行，工具已锁定为纯只读诊断模式，绝不干扰看门狗！`
3. **零写入约束**：
   本工具绝不调用 `schtasks /end`、`schtasks /change` 或 `Stop-Process`，严禁干扰看门狗的判定与轮询周期。
4. **镜像安全归档**：
   D 盘原看门狗目录已完整以**只读镜像**形式归档在 U 盘 `backups\Network-Reference-Watchdog\`，D 盘原始文件绝对保持未被改动状态。

## 3. 单实例并发互斥锁

为防止用户在排查网络时连续多次双击启动工具，导致并发探测消耗网络资源或产生日志写入冲突，主程序引入了全局互斥体（Global Mutex）：
- **互斥体名称**：`Local\NetworkDiagnosticsToolkit_Running_Mutex`
- **逻辑实现**：
  ```powershell
  $script:Mutex = New-Object System.Threading.Mutex($false, "Local\NetworkDiagnosticsToolkit_Running_Mutex")
  if (-not $script:Mutex.WaitOne(0, $false)) {
      Write-Warning "已有网络诊断工具实例正在运行中，禁止重复启动！"
      exit 0
  }
  ```
- **生命周期**：在程序正常退出或异常终止的 `finally` 块中，自动执行 `$script:Mutex.ReleaseMutex()` 与 `$script:Mutex.Dispose()`，保证锁的原子性释放。

## 4. 驱动只读备份边界

当执行 `Action: BackupDrivers` 时，为防止因磁盘写满引发系统异常或驱动损坏：
1. **可用空间强制校验**：
   程序预先计算 U 盘所在分区的空闲字节数，若可用空间低于 `500 MB`，直接拒绝导出并报错返回。
2. **官方受控命令**：
   严格仅调用：
   `pnputil.exe /export-driver * <U盘备份目录>`
3. **严禁逆向操作**：
   禁止包含 `/add-driver`（安装驱动）、`/delete-driver`（删除驱动）或 `/restart-device`。

## 5. 敏感信息脱敏规范 (Data Sanitization)

生成的诊断包可能需要发送给技术人员或上传分析，必须执行严格的脱敏过滤：
- **Wi-Fi SSID**：保留前 2 个字符与末尾 1 个字符，中间全部替换为 `***`（例如 `TP***1`）。
- **物理 MAC 地址**：前 4 段（OUI）脱敏为 `XX:XX:XX:XX:`，仅保留末尾两段用于接口区分。
- **公网 IPv4 地址**：A/B 类公网地址保留第一段，后三段掩码处理（例如 `114.***.***.***`）。
- **内网保留私网地址**（`192.168.x.x`、`10.x.x.x`、`172.16-31.x.x`）：属于排查网关的关键信息，予以保留。

## 7. 新增高级诊断能力的只读安全红线

本工具箱新增的高级诊断功能全部严格遵守纯只读原则，杜绝任何隐式系统状态篡改：

1. **IPv6 双栈探测只读红线**：
   - 仅调用 `Get-NetRoute -AddressFamily IPv6` 与 `Get-NetIPAddress -AddressFamily IPv6` 读取路由表与单播地址。
   - 严禁调用 `Set-NetIPInterface`、`New-NetRoute` 或 `Remove-NetRoute`。
2. **网卡电源管理只读红线**：
   - 仅调用 `Get-NetAdapterPowerManagement` 读取 `AllowComputerToTurnOffDevice` 状态。
   - 严禁调用 `Set-NetAdapterPowerManagement` 或 `Set-NetAdapterAdvancedProperty` 自动修改节能设置；检测到开启时仅输出文本提示，指导用户手动在设备管理器操作。
3. **无线链路质量只读红线**：
   - 仅调用 `netsh wlan show interfaces` 查询连接速率与信号强度。
   - 严禁调用 `netsh wlan connect`、`disconnect` 或 `delete profile`。
   - 对提取到的 SSID 与 BSSID 执行强制字符串掩码脱敏。
4. **DHCP 租约信息只读红线**：
   - 仅通过 WMI/CIM 读取 `Win32_NetworkAdapterConfiguration` 的 `DHCPLeaseObtained` 与 `DHCPLeaseExpires` 计算剩余到期时间。
   - 严禁调用 `ipconfig /renew`，坚决不向 DHCP 服务器发送任何续租报文。
5. **NCSI 连通性判定只读红线**：
   - 仅读取 `Get-NetConnectionProfile` 与注册表 `HKLM:\SYSTEM\CurrentControlSet\Services\NlaSvc\Parameters\Internet`。
   - 严禁修改注册表探针地址或篡改 `EnableActiveProbing` 键值。
6. **核心网络服务状态只读红线**：
   - 仅通过 `Get-Service` 查询 `Dhcp`、`Dnscache`、`nsi`、`Wlansvc`、`NlaSvc`、`WinHttpAutoProxySvc` 的运行状态。
   - 严禁调用 `Start-Service`、`Stop-Service` 或 `Restart-Service`。
