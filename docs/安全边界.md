# Windows 便携网络只读诊断工具箱 - 安全边界与红线规则

================================================================================
【核心原则】避免再次断网 (Zero Network Impact) | 证据优先 (Evidence First)
================================================================================

> **适用范围声明（2026-09 更新）**
> 本文第 1 ~ 7 章的全部红线，适用于**只读诊断子系统**：入口 `START-DIAGNOSIS.cmd`、
> 主控 `app\NetworkDiagnostics.ps1` 及其 4 个诊断模块。该子系统永久保持纯只读，不得放宽。
> 经用户明确授权新增的**受限恢复子系统**（入口 `START-SAFE-RECOVERY.cmd`）只被授权两项写操作，
> 其精确边界见**第 8 章**。第 8 章是对第 1 章的**范围受限例外**，不改变诊断子系统的任何承诺。

## 1. 核心安全红线 (Forbidden Operations)

本工具箱在代码架构、指令调用与业务逻辑层面，**绝对禁止**包含以下任何一项具有网络状态变更副作用的操作：

| 类别 | 严禁调用的命令 / API | 风险说明 | 本工具合规实现 |
| :--- | :--- | :--- | :--- |
| **网卡状态修改** | `Disable-NetAdapter`<br>`Enable-NetAdapter`<br>`Restart-NetAdapter` | 重启物理网卡会导致 Wi-Fi 芯片瞬时掉电或驱动重置，极易诱发固件崩溃断网 | 仅调用 `Get-NetAdapter`、`Get-NetAdapterStatistics` 进行只读查询 |
| **IP / 租约变更** | `ipconfig /release`<br>`ipconfig /renew`<br>`arp -d` | 释放 IP 会立即中断已有 TCP 连接；DHCP 续租失败会导致接口掉线 | 仅调用 `Get-NetIPAddress`、`Get-NetIPConfiguration` 进行只读信息读取 |
| **协议栈与重置** | `netsh winsock reset`<br>`netsh int ip reset`<br>`netcfg -d` | 重置底层 Winsock 目录和 TCP/IP 栈会破坏 LSP、VPN 虚拟网卡驱动并强制要求重启 | 严禁包含此类指令；相关旧版代码已全量物理隔离封存 |
| **DNS 缓存修改** | `ipconfig /flushdns`<br>`Clear-DnsClientCache` | 刷新本地 DNS 解析缓存可能导致瞬时解析延迟增加或冲突 | 仅使用 `Resolve-DnsName` 测试单次域名解析能力 |
| **代理注册表篡改** | `Set-ItemProperty ... Internet Settings`<br>`netsh winhttp reset proxy` | 强行重置代理可能破坏企业内网、合规网关或特定网络分流环境 | 仅通过注册表只读读取 `ProxyEnable`、`ProxyServer` 及 `netsh winhttp show proxy` |
| **网络凭据泄露** | `netsh wlan show profile key=clear` | 明文导出 Wi-Fi 密码违背企业与个人数据安全准则 | 绝不抓取明文密钥；所有 Wi-Fi SSID 均进行字符串掩码脱敏 |
| **系统持久化污染** | `schtasks /create`<br>`sc.exe create`<br>`New-Service`<br>写入注册表 Run 键 | 留在宿主机上的后台脚本会破坏宿主机独立性，随时间推移失控 | 拔出即走，不创建任何驻留进程、计划任务或服务 |

## 2. 本地看门狗避让与互斥机制

宿主机本地 D 盘已常驻运行着由系统计划任务托管的看门狗脚本：
- **计划任务名称**：`NetworkRecoveryWatchdog`
- **监控脚本路径**：`D:\agentNeural Network Knowledge Base\network\auto_network_recovery.ps1`
- **托管管理脚本**：`D:\agentNeural Network Knowledge Base\network\manage_watchdog.ps1`

### 互斥防御策略
1. **进程与任务静态侦测**：
   工具启动初始化时，`Test-LocalWatchdogRunning` 会主动扫描：
   - 计划任务 `NetworkRecoveryWatchdog` 是否存在且处于 `Running` 状态；
   - 运行中进程是否包含 `auto_network_recovery.ps1`。
2. **强制降级只读模式**：
   一旦发现看门狗处于活动状态，控制台立即高亮输出提示：
   `[WARN] 检测到系统本地网络看门狗正在运行，工具已锁定为纯只读诊断模式，绝不干扰看门狗！`
3. **零写入约束**：
   本工具绝不调用 `schtasks /end`、`schtasks /change` 或 `Stop-Process`，严禁干扰看门狗的判定与轮询周期。
4. **镜像安全归档**：
   D 盘原看门狗目录已完整以**只读镜像**形式归档在 U 盘 `backups\Network-Reference-Watchdog\`，D 盘原始文件绝对保持未被改动状态。

## 3. 单实例并发互斥锁

为防止用户在排查网络时连续多次双击启动工具，导致并发探测消耗网络资源或产生日志写入冲突，主程序引入了全局互斥体（Global Mutex）：
- **互斥体名称**：`Local\NetworkDiagnosticsToolkit_Running_Mutex`
- **逻辑实现**：
  ```powershell
  $script:Mutex = New-Object System.Threading.Mutex($false, "Local\NetworkDiagnosticsToolkit_Running_Mutex")
  if (-not $script:Mutex.WaitOne(0, $false)) {
      Write-Warning "已有网络诊断工具实例正在运行中，禁止重复启动！"
      exit 0
  }
  ```
- **生命周期**：在程序正常退出或异常终止的 `finally` 块中，自动执行 `$script:Mutex.ReleaseMutex()` 与 `$script:Mutex.Dispose()`，保证锁的原子性释放。

## 4. 驱动只读备份边界

当执行 `Action: BackupDrivers` 时，为防止因磁盘写满引发系统异常或驱动损坏：
1. **可用空间强制校验**：
   程序预先计算 U 盘所在分区的空闲字节数，若可用空间低于 `500 MB`，直接拒绝导出并报错返回。
2. **官方受控命令**：
   严格仅调用：
   `pnputil.exe /export-driver * <U盘备份目录>`
3. **严禁逆向操作**：
   禁止包含 `/add-driver`（安装驱动）、`/delete-driver`（删除驱动）或 `/restart-device`。

## 5. 敏感信息脱敏规范 (Data Sanitization)

生成的诊断包可能需要发送给技术人员或上传分析，必须执行严格的脱敏过滤：
- **Wi-Fi SSID**：保留前 2 个字符与末尾 1 个字符，中间全部替换为 `***`（例如 `TP***1`）。
- **物理 MAC 地址**：前 4 段（OUI）脱敏为 `XX:XX:XX:XX:`，仅保留末尾两段用于接口区分。
- **公网 IPv4 地址**：A/B 类公网地址保留第一段，后三段掩码处理（例如 `114.***.***.***`）。
- **内网保留私网地址**（`192.168.x.x`、`10.x.x.x`、`172.16-31.x.x`）：属于排查网关的关键信息，予以保留。

## 7. 新增高级诊断能力的只读安全红线

本工具箱新增的高级诊断功能全部严格遵守纯只读原则，杜绝任何隐式系统状态篡改：

1. **IPv6 双栈探测只读红线**：
   - 仅调用 `Get-NetRoute -AddressFamily IPv6` 与 `Get-NetIPAddress -AddressFamily IPv6` 读取路由表与单播地址。
   - 严禁调用 `Set-NetIPInterface`、`New-NetRoute` 或 `Remove-NetRoute`。
2. **网卡电源管理只读红线**：
   - 仅调用 `Get-NetAdapterPowerManagement` 读取 `AllowComputerToTurnOffDevice` 状态。
   - 严禁调用 `Set-NetAdapterPowerManagement` 或 `Set-NetAdapterAdvancedProperty` 自动修改节能设置；检测到开启时仅输出文本提示，指导用户手动在设备管理器操作。
3. **无线链路质量只读红线**：
   - 仅调用 `netsh wlan show interfaces` 查询连接速率与信号强度。
   - 严禁调用 `netsh wlan connect`、`disconnect` 或 `delete profile`。
   - 对提取到的 SSID 与 BSSID 执行强制字符串掩码脱敏。
4. **DHCP 租约信息只读红线**：
   - 仅通过 WMI/CIM 读取 `Win32_NetworkAdapterConfiguration` 的 `DHCPLeaseObtained` 与 `DHCPLeaseExpires` 计算剩余到期时间。
   - 严禁调用 `ipconfig /renew`，坚决不向 DHCP 服务器发送任何续租报文。
5. **NCSI 连通性判定只读红线**：
   - 仅读取 `Get-NetConnectionProfile` 与注册表 `HKLM:\SYSTEM\CurrentControlSet\Services\NlaSvc\Parameters\Internet`。
   - 严禁修改注册表探针地址或篡改 `EnableActiveProbing` 键值。
6. **核心网络服务状态只读红线**：
   - 仅通过 `Get-Service` 查询 `Dhcp`、`Dnscache`、`nsi`、`Wlansvc`、`NlaSvc`、`WinHttpAutoProxySvc` 的运行状态。
   - 严禁调用 `Start-Service`、`Stop-Service` 或 `Restart-Service`。

## 8. 受限安全恢复子系统的授权边界 (Scoped Exception)

本章仅适用于独立恢复子系统，且**不影响**只读诊断子系统的任何承诺：

- 入口：`START-SAFE-RECOVERY.cmd`
- 主控：`app\NetworkSafeRecovery.ps1`
- 只读观察层：`app\modules\SafeRecoveryObservation.psm1`
- **唯一被授权执行写操作的文件**：`app\modules\SafeRecoveryActions.psm1`
- 专用配置：`app\SafeRecovery.Config.psd1`

### 8.1 用户授权原文

> 同意新增独立安全恢复模块；允许切换 701/702 和重新获取无线 DHCP，
> 但禁止修改代理、Winsock、注册表及删除 Wi-Fi 配置文件。

### 8.2 被授权的写操作（仅此两项，不得扩充）

| 序号 | 授权命令 | 强制前置校验 |
| :--- | :--- | :--- |
| 1 | `netsh wlan connect name=<配置文件> interface=<无线网卡>` | 配置文件必须在白名单 `@('701','702')` 内；名称必须匹配 `^[A-Za-z0-9_-]{1,32}$`；必须显式传入接口名，禁止由 netsh 自行选择接口 |
| 2 | `ipconfig /renew "<无线网卡名称>"` | 必须按 GUID 重新解析网卡且唯一命中；必须仍被识别为物理 802.11 网卡；网卡名称必须与连接阶段一致；该接口 IPv4 必须为 `Dhcp=Enabled`；**禁止无接口名的全局续租** |

### 8.3 恢复子系统内的永久禁止清单

即使在本子系统内，以下操作同样**永久禁止**，不得以任何理由新增：

| 类别 | 永久禁止 |
| :--- | :--- |
| **IP 释放** | `ipconfig /release`、`arp -d`、`ipconfig /registerdns` |
| **协议栈重置** | `netsh winsock reset`、`netsh int ip reset`、`netcfg -d` |
| **DNS 缓存** | `ipconfig /flushdns`、`Clear-DnsClientCache` |
| **代理链路** | 任何对 WinINET / WinHTTP 代理、`Internet Settings` 注册表、Clash / ProxyBridge / verge-mihomo 进程的修改 |
| **注册表** | 任何 `Set-ItemProperty` / `New-ItemProperty` / `Remove-ItemProperty` 写入 |
| **Wi-Fi 配置文件** | `netsh wlan add profile` / `delete profile` / `set profileparameter` / `export profile` / `disconnect`；`key=clear` |
| **网卡状态** | `Disable-NetAdapter`、`Enable-NetAdapter`、`Restart-NetAdapter`、`Set-NetAdapter*` |
| **接口与路由配置** | `Set-NetIPInterface`、`Set-NetIPAddress`、`New-NetRoute`、`Remove-NetRoute` |
| **服务与持久化** | `Start/Stop/Restart-Service`、`New-Service`、`schtasks`、Run 键 |
| **看门狗** | `Stop-Process`、`schtasks /end`、`schtasks /change`；仅允许**只读**查询其状态 |
| **失败升级** | 严禁在连接或续租失败后自动升级到上述任何手段；失败必须停止并落盘日志 |

### 8.4 强制安全门（缺一不可）

1. **白名单硬编码（含不可逾越的代码级上界）**：
   - `app\modules\SafeRecoveryObservation.psm1` 内的 `$script:HardCodedAllowedProfiles = @('701','702')`
     是**代码级上界**：`SafeRecovery.Config.psd1` 只能是它的子集，写入任何其他名称都会在加载时被拒绝。
   - 主控 `-TargetProfile` 使用 `ValidateSet('701','702')`。
   - 配置加载时校验；写操作函数内再次同时校验配置白名单与代码级白名单。
   - 因此**编辑 U 盘上的配置文件无法把授权范围扩大到 701/702 以外**。
2. **网卡唯一性**：识别到 0 张或 ≥2 张物理无线网卡时立即中止，绝不猜测；
   `-InterfaceGuid` 只能在**已识别的无线网卡**中消除歧义，**不能**引入非无线网卡。
3. **人工确认**：必须逐字输入 `YES`（大小写敏感）；无任何跳过参数，`-Confirm:$false` 也无法绕过。
4. **单实例互斥**：与诊断工具共用 `Local\PortableNetworkDiagnosis`，防止诊断与恢复同时操作同一网卡。
5. **看门狗只读避让**：检测到活动看门狗时高亮警告并计入日志，**绝不干预**。
6. **退出码与后置条件**：`netsh wlan connect` 与 `ipconfig /renew` 的 `$LASTEXITCODE` 都必须检查
   （连接非零即判该次尝试失败；续租非零记入失败原因）；且必须轮询确认
   「配置文件正确 + 介质 Connected + IPv4 非 `169.254.*` + 该接口存在默认路由」才判定成功。
   网关 ICMP 结果**仅记录**，不作为成功或失败的判定条件，且**不得**放在轮询循环内执行。
7. **不创建配置文件**：只使用本机**已保存**的配置文件；未保存的一律跳过并记录。
8. **日志脱敏**：日志写入 U 盘 `logs\safe-recovery\`；禁止记录 Wi-Fi 密钥、BSSID、
   配置文件 XML 与公网 IP；白名单以外的 SSID 一律掩码。
9. **当前可用则不动它**：恢复前若已在某个白名单配置文件上且网络可用，必须直接返回成功且
   **不做任何修改**；只有用户显式指定 `-TargetProfile` 才允许主动切换，且必须在确认前红字警告
   「将主动断开当前可用网络」。
10. **失败尽力回退**：发生过写操作而所有尝试均失败时，必须尽力重新连回操作前那个白名单配置文件
    （只做一次白名单内的 `netsh wlan connect`，不得附加任何其他动作），使最坏结果不差于操作前。
11. **关联判定双来源**：关联状态必须同时参考 WLAN 服务与 NLA，任一确认即算关联。
    只信任 NLA 会因命名滞后或 `701 2` 去重后缀把成功误判为失败，进而触发不必要的切换。
12. **异常不得升级为误报**：单次尝试内的异常只能让该次尝试失败并写入日志，不得终止整个流程；
    一旦发生过任何写操作，失败必须报「已尝试」而**不得**报成「未做任何修改的环境错误」。
13. **DHCP 状态未知即拒绝**：`Dhcp` 查询失败（未知）必须与「明确未启用 DHCP」区分，两者都拒绝续租，
    但提示信息不得把「查询失败」谎报为「静态 IP 配置」。
14. **红线可被自动验证**：`tests\Invoke-SafeRecoveryTests.ps1` 对本章禁止清单执行静态扫描，
    并验证受限写操作层内 `connect` 与 `renew` 调用点各自恰好 1 处、只读观察层内为 0 处。

### 8.5 明确的能力边界（不得夸大宣传）

本子系统**不能**保证修好 `701`。若 AP / 路由器侧未回应 DHCP（无 OFFER/ACK），
客户端脚本无法凭空生成租约。此时它只会如实报告失败、保留证据并停止，
由用户使用 `START-DIAGNOSIS.cmd` 继续取证或检查 AP 侧配置。
